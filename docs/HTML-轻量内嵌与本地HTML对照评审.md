# 内嵌 HTML 轻量化 + 打开本地 .html 左右对照评审

> 分支 `feat/html-lite-and-open-html`（基于 1.6.4，main=`5543922c`）。
> 本文是这一轮的设计说明：为什么改、轻重怎么判、降级长什么样、.html 怎么打开、边界在哪。

## 1. 背景：4.4MB PRD 白屏卡死

事故文件：`AI会学_题目会话与讲解视频_PRD.md`（4,477,024 字节）。文末有一个 HTML 块，4.2MB，其中一行是
`<script id="wbSourceData" type="text/plain">` 里的 base64 载荷，长 4,025,777 个字符。

### 根因（V8 CPU profile 定位）

1. 块里有 `<script>`，于是编辑器为它建「源码视图」：`HTMLContainer` → 代码块 → `CodeBlockContent.update`
   → `prism.highlightElement`，用 markup 语法高亮。
2. markup 语法会把 `<script>` 的正文**嵌套成 JavaScript 语法**再高亮一遍（不管 `type="text/plain"`）。
3. Prism 的 JavaScript `function` / `function-variable` 两条规则形如
   `#?(?!\s)[_$a-zA-Z\xA0-\uFFFF](?:(?!\s)[$\w\xA0-\uFFFF])*(?=\s*…\()`：遇到一长段连续的标识符字符时，
   每个起点都要贪婪吃到段尾再回退，整体 **O(n²)**。
4. ASCII HTML 的 base64 几乎不含 `+` `/`（实测 2 万字符里只有 3 个），整行就是一段几百万字符的标识符串。

实测（happy-dom，同一机器）：

| 标识符段长度                      | 初始化耗时                         |
| --------------------------------- | ---------------------------------- |
| 1 万字符                          | 291 ms                             |
| 2 万字符                          | 1.2 s                              |
| 2.5 万 / 5 万 / 10 万（整篇文档） | 1.8 s / 6.7 s / 26.6 s             |
| 400 万（事故文件）                | 外推约 50 分钟（表现为白屏、转圈） |

对照组：同长度的普通文字 1ms、全是 `+/` 的串 3ms，说明问题出在「长标识符段 + Prism JS 语法」这个组合，不在体积本身。

## 2. 修法：两层

### 第一层：代码高亮预算（根治 Prism 平方级回退）

`packages/muya/src/utils/codeHighlightBudget.ts`。满足任一条件就不交给 Prism，按纯文本显示：

- 代码总长 > **256K 字符**（`CODE_HIGHLIGHT_MAX_CHARS`）；
- 含一段 ≥ **1000 个字符**的连续标识符字符（`CODE_HIGHLIGHT_MAX_TOKEN_RUN`）。

1000 的依据：平方级曲线在 1 万字符时已近 300ms，1000 字符约 3ms；正常代码里的标识符很少超过 100 个字符，
1000 只会命中 base64、压缩产物、长哈希这类本来就没有高亮价值的内容。

扫描本身是逐字符线性扫描，不用正则：`[\w$]{1000}` 这类正则对同一输入同样是平方级的。

接入点：代码块 `CodeBlockContent.update()`、退格时的 `prism.tokenize`、导出/预览用的 `getHighlightHtml`。
这一层对所有代码块生效，不只是 HTML 块。

### 第二层：内嵌 HTML 轻重分级

`packages/muya/src/utils/htmlWeight.ts`，`classifyHtmlWeight(html)`。

即使高亮不再卡死，几 MB 的源码仍然要进 DOM、要断行布局，几 MB 的源码也要 postMessage 进沙箱帧。
文档内嵌的定位是「图表、小组件」，整页原型应该是独立的 .html 文件。所以第二层是产品规则，不只是性能兜底。

## 3. 轻重判定

### 规则

满足任一条即为**重量 HTML**：

| 条件           | 阈值                     | 常量                  |
| -------------- | ------------------------ | --------------------- |
| 块源码总长     | > 256 Ki 字符（262,144） | `HTML_LITE_MAX_CHARS` |
| 块内最长的一行 | > 64 Ki 字符（65,536）   | `HTML_LITE_MAX_LINE`  |

**有没有 `<script>` 不参与判定**。轻量图表几乎都带脚本（ECharts、Chart.js 的初始化代码），
按脚本分级会把最该保留的图表误伤；脚本只在降级卡片里作为信息展示。

### 阈值依据（用户本机真实文档分布）

扫描 `~/claude/projects`、`~/deepseek`、`~/cursor` 下所有 .md 的 HTML 块（≥ 2K 字符的共 34 个，排除实验文件）：

| 类别                                           | 体积      | 最长行                | 判定                     |
| ---------------------------------------------- | --------- | --------------------- | ------------------------ |
| 图表、小组件                                   | ≤ 14 KB   | 几百字符              | 轻量                     |
| 整页内联原型（测评活动管理、搭子亲密度测评等） | 54–129 KB | 594–7,477             | 轻量（保持内嵌，无回退） |
| 选科定位测评 PRD                               | 540 KB    | 185,255（base64 PNG） | 重量                     |
| 事故 PRD                                       | 4.2 MB    | 4,025,777             | 重量                     |

- 体积阈值 256Ki ≈ 已知最大轻量块（129KB）的 2 倍，留了余量；离最小的重量块（540KB）也有 2 倍。
- 最长行阈值 64Ki ≈ 已知轻量块最长行（7,477）的 8 倍。超长单行几乎只来自内联 base64 图片、字体或压缩产物，
  它们正是让源码视图和 postMessage 变慢的东西。
- 两条阈值都取 2 的幂，便于记忆和对外说明（「256K / 64K」）。

### 验收时间阈值

**打开到可交互 ≤ 2 秒**（打包形态，M 系列 Mac）。实测：

| 文档                                                                | 改前           | 改后                                    |
| ------------------------------------------------------------------- | -------------- | --------------------------------------- |
| 事故 PRD 4.4MB（引擎初始化，happy-dom）                             | 不返回（白屏） | **93–99 ms**                            |
| 事故 PRD 4.4MB（Electron dev 形态，从欢迎页点开到正文出现，含建窗） | 白屏           | **1.09 s**，之后两帧 21ms（主线程空闲） |
| 选科定位测评 PRD（540KB 块）                                        | 646 ms         | 93 ms                                   |
| user-md-copy（两个 119KB 轻量原型）                                 | 847 ms         | 788 ms（仍内嵌，2 个帧）                |
| 合成：1MB / 4MB 脚本块                                              | 外推数分钟     | 13 / 14 ms                              |

dev 形态没压缩、走 vite 开发服务器，打包形态只会更快。

## 4. 降级形态

重量块在编辑器里显示一张卡片，不建 iframe，不渲染源码：

```
┌──────────────────────────────────────────────┐
│ 大体积 HTML，未在文档内渲染                      │
│ 4.2 MB · 最长行 4,025,777 字符 · 含脚本          │
│ [并列查看]  [另存为 .html 文件…]                 │
│ 文档内只渲染轻量 HTML（如图表）。整页原型请另存为  │
│ .html 文件，与文档左右对照评审。                  │
└──────────────────────────────────────────────┘
```

- **并列查看**：把块源码建成一个只读 html 快照标签（无路径，标签悬停提示「<文档> 中 HTML 块的快照」），
  直接放进右侧分屏；用和内嵌块同一个引导页（`html-frame.html`）、同一个沙箱等级渲染整页。
  左栏文档不动，所以老文档不改源码也能做左右对照。
- **另存为 .html 文件…**：主进程弹保存框，默认放在当前文档同目录、文件名取页面 `<title>`。
  写盘前去掉块前的 `<!--momark-frame …-->` 尺寸标记、补回 `<!DOCTYPE html>`。写完把这个文件作为 html 标签放进右侧分屏。
  文档本身不改：要不要把块换成一条指向该文件的链接，由作者决定。
- 块悬停工具条上的「并列查看」对轻量、重量块都有效，统一取块源码建快照标签。
- 源码不丢、不改：md 原样读写，`getMarkdown()` 逐字节一致（单测钉住）。点进块（编辑态）才渲染源码，
  这时高亮预算保证不卡死，但几 MB 的纯文本编辑仍然慢，见第 8 节。
- 未激活时源码容器 `display:none`（CSS `figure.mu-html-heavy:not(.mu-active)`），几 MB 的文本不参与布局。

### 导出

| 导出形态          | 轻量脚本块                | 重量脚本块                                       | 不含脚本的重量块  |
| ----------------- | ------------------------- | ------------------------------------------------ | ----------------- |
| HTML（活帧）      | 沙箱 iframe，尺寸按编辑器 | 沙箱 iframe（srcdoc），跟随页面宽度、高 800px    | 原样（静态 HTML） |
| PDF / 打印 / docx | 按编辑器尺寸截图          | 一行说明：「大体积 HTML（4.2 MB）未随导出渲染…」 | 原样              |

重量块不再参与「帧 ↔ 含脚本源码」的一一对应（编辑器里它没有帧）。不这样做的话，
同一篇文档里的轻量图表会因为数量对不上而整篇按原样导出，导出物里一片空白或者露出源码。

## 5. 打开本地 .html：入口

.html 文件作为**只读文档标签**打开：和 md 标签在同一条标签栏里，可切换、可关闭、可拖进右侧分屏。
标签不可编辑、不会变成「未保存」，保存 / 另存为 / 导出 / 重命名对它不生效。所有入口都走主进程同一条
`EditorWindow.openTabs`：按扩展名分流，md 建编辑标签，html 读盘后发 `mt::open-html-tab` 建只读标签；
两者共用去重（同一路径只开一个标签，再开就切过去）、文件监视与「最近文件」登记。

| 入口                                                            | 行为                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------ |
| 菜单「文件 → 打开…」（⌘O）                                      | 过滤器包含 .html/.htm；多选时整批作为标签打开                |
| 拖放 .html 到窗口                                               | 作为标签打开                                                 |
| md 正文里指向本地 .html 的链接（如 `[原型](proto/index.html)`） | 作为标签打开（原先交给系统打开）                             |
| 右栏底部「打开文件…」/ 右栏最近文件                             | 选 md 照旧进分屏；选 html 建标签并直接放进分屏，当前标签不动 |
| Finder 打开方式 / 拖到 Dock 图标 / 命令行 `墨记 a.html`         | 与 md 相同的窗口选择规则，作为标签打开                       |
| 欢迎页「打开文件」/「最近文件」                                 | 新窗口里作为标签打开                                         |
| 块工具条 / 重量块卡片「并列查看」/「另存为 .html 文件…」        | 见第 4 节                                                    |

`electron-builder.yml` 为 html/htm 登记了 `role: Viewer`、`rank: Alternate`：墨记出现在 Finder 的「打开方式」里，
但不抢浏览器的默认打开。

html 标签右下角（悬停显示）的控制条：`− 100% +` 缩放，加上本地文件专有的「重新载入」（按原路径重读）、
「在浏览器打开」与「在文件夹中显示」。快照标签没有路径，只有缩放。标签悬停显示完整路径与「只读」；
同名标签按路径末段区分（`index.html · proto-a`）。

磁盘上的文件被改动时，标签顶部出「已在磁盘上发生变更，是否重新载入」横幅，确认后重读；文件被删时只提示，
页面保留最后一次读到的内容。两种情况都不把标签标成未保存。

## 6. 左右对照的操作路径

**新文档（推荐）**：md 与原型分开存放，正文里用链接引用。

1. 打开 PRD.md。
2. 点正文里的原型链接；或 ⌘O 选 `prototype.html`；或直接把 .html 拖进窗口。原型作为标签打开。
3. 把原型标签拖到右侧分屏（与 md 标签分屏的操作相同），左栏继续写 PRD；拖分隔线调宽度，右下角可缩放。
   也可以直接用右栏底部「打开文件…」选 html，一步进分屏。
4. 改了原型文件后，点横幅里的确认或控制条上的「重新载入」。
5. 不需要对照时，把分屏还回标签栏或直接关闭标签。

**老文档（已内嵌整页原型）**：

1. 打开文档。重量块显示为卡片，文档秒开。
2. 点「并列查看」：块源码作为只读快照标签进右侧分屏，文档不改。
3. 想长期这样用：点「另存为 .html 文件…」，原型落成独立文件并作为标签进分屏。之后可以把块换成链接。

## 7. 安全模型（沿用现状，未放宽）

- html 标签与编辑器内嵌块共用 `html-frame.html` 引导页，iframe 只有 `sandbox="allow-scripts"`，
  没有 `allow-same-origin`，是不透明源：页面里访问 `localStorage`、cookie、`parent.document` 一律 SecurityError
  （Electron 实测）。没有 Node 能力，也没有 preload。
- 不透明源的帧读不到 `file://`，本地图片协议也只放行图片。所以打开本地 .html 时，渲染层先用已有的
  `htmlInline` 逻辑把**同目录（含子目录）**的 CSS（`<link rel=stylesheet>`）、JS（`<script src>`）、图片（`<img src>`、CSS 里的 `url()`）
  读进源码再投递。预览版保留 `<!DOCTYPE html>` 和原文空行（标准模式渲染，
  `<pre>` 内容不变）；写进 .md 的内嵌版行为不变（剥 doctype、压空行，`insertHtmlBlock.spec.ts` 钉住）。
- **内联只读 html 所在目录**：内联进来的内容页面脚本都读得到，所以 `../x`、绝对路径 `/etc/passwd`、`..%2f` 编码、
  目录里指向外面的符号链接一律不读。判定按 realpath：先按 html 目录解析出绝对路径，再跟随符号链接取真实路径，
  两步都必须落在 html 目录（同样取 realpath）之内。html 标签和「粘贴 html → 内嵌到文档」共用这一条通道。
- **内联有体积上限**（`common/html/limits.ts`）：单个资源 8MB；整份内联结果（入口原文 + 资源，图片按 base64 膨胀后计）
  不超过 32MB，与打开 .html 的入口上限一致——内联产物不应比直接打开的文件更大。读之前先 stat，不会先整份读进来再判断。
- 没内联上的资源按原因汇总提示：在 html 所在目录之外 / 不存在 / 超过体积上限 / 读取失败。
- 主进程的新通道都做二次校验：`mt::html::read` / `mt::html::open-externally` 只放行真实存在的 .html/.htm
  （符号链接按最终目标判断，目标也必须是 .html/.htm，否则 `notes.html -> ./deploy` 会被当网页直接运行）；
  读文件有 32MB 上限，超限会通知而不是卡住窗口。「粘贴 html → 内嵌」读入口也走 `mt::html::read`，同一套上限与编码探测。
  「另存为 .html」写完直接把写入内容交给渲染层建标签、不回读，所以大块不会「写成功却报保存失败」。
- 极速模式不建任何网页帧：html 标签照常打开，但只显示「极速模式不渲染网页」占位与「在浏览器打开」；重量块卡片照常显示。

## 8. 已知边界

- **.html 不进侧栏文件树**（只认 Markdown）；会进「最近文件」。
- **切走 html 标签再切回会重建页面**：iframe 不常驻，页面里的脚本状态（滚动位置、展开的面板）不保留。
- **快照标签与源文档不联动**：改了文档里的块，已打开的快照不跟着变，需要重新点「并列查看」。
- **多页原型的页内跳转不支持**：页面里 `<a href="page2.html">` 在沙箱帧里会跳到引导页的相对地址（空白）。
  建议单文件原型；多页原型用「在浏览器打开」。
- **只内联 html 所在目录（含子目录）里、以相对路径引用的资源**：引用上级目录（`../shared/app.css`）的多项目共用资源同样不内联，
  需要时把资源拷进 html 所在目录。`fetch()`、动态 `import()`、CSS `@import`、字体、视频这类运行时加载的本地资源读不到。
  远程 http(s) 资源照常加载。
- **编辑重量块的源码仍然慢**：点进块后几 MB 的纯文本照样要布局。卡死已经消除（高亮预算），但不适合在编辑器里改，
  应该另存为 .html 用外部编辑器改。
- **选科定位测评 PRD 的行为有变化**：它的 540KB 块（一行 185K 字符的 base64 图片）以前内嵌渲染，现在显示为卡片，
  需要点「并列查看」。这是按规则有意为之；打得开、能读、源码不变。
- 阈值是常量，不提供设置项（第五节「不做预防性配置」）。真遇到误判，改常量并补单测。
- 「另存为 .html 文件…」用的是系统保存框，没有自动化 GUI 用例覆盖；主进程写盘逻辑和 doctype 处理有单测。
